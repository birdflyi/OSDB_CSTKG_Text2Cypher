# E3 来源需求与范围边界

分支：`codex/ch7-e3-demand-coverage`。从 E1 阶段提交 `47491a3` 派生；原六服务编译器及提示不改。

## 判断边界

E1/E2 支持“在已测共同能力交集没有观察到正确完成率退化”。它不是正式不劣性证明，也不证明目录外覆盖、完整历史事实或跨项目不退化。后者由 E3/E4 单独检验。

## 来源收集完成，正式需求集尚未冻结

采用两个可追踪来源，先收集再作本地能力判断：

- [RepoQA revision-1 复制包](https://zenodo.org/records/17162221)：按十个发布任务组，各取出现最多的 query_no，平局取较小值，再取该组第一条原文。只提取问题与来源，不复制查询和答案。发布任务组／歧义标签只作来源信息，不当作本地 Gold。
- [CHAOSS Evolution 指标库](https://github.com/chaoss/wg-evolution/tree/ada8c11ee342fdc64e94f5f894676565aa2e6506/focus-areas)：收集全部 22 个非 README 指标文件，固定版本与文本摘要；不按服务是否支持筛选。

合计 32 个来源条目，不等于 32 个独立语义目标。提交计数等需求需在日期类型、时间窗和目标定义明确后去重。原文在仓库外；公开索引为 `E3_SOURCE_INDEX.json`。收集器先以 `13737ac` 提交，再进入本地参考编制。v1 首条抽样存在发布组与首条语义不一致风险；保留 v1，v2 使用上述众数规则，仍需逐条复核。

这些是便利来源集合，不是真实用户分布、独立人类标注或 RepoQA 原样复现。文件修改、缺陷引入和完整历史任务若缺信息，必须记录为图证据缺口，不能拿引用关系替代修复／因果关系。

## 六目标可行性试验准备完成

从来源中先编制六个能建立独立参考的目标：新增 Issue、关闭 Issue、新增 PR 列表、接受 PR 数、明确拒绝的 PR 列表、接受／拒绝比。固定七月窗口 `[2023-07-01,2023-08-01)` 和主项目 ID 字符串前缀。

所有需求明确限定“提供图中观察到的事件”。去重按实体 ID；拒绝 PR 必须有显式 `pull_merged=False`，不能从没有合并边推断；关闭不推断当前状态，也不因后续重开回改本次观察计数。此为源指标的可审计操作化，不等于完整 GitHub 历史上的 CHAOSS 指标复现。

| 检查 | 结果 |
|---|---|
| 实验目录测试 | 31/31 |
| CSV 独立集合参考与另写 Cypher | Redis 6/6，DuckDB 6/6 |
| 引擎 | 保留 E1 的六服务目录、配对示例、模型设置和一次修复上限 |
| 共享信息修订 | 两种表示均获得全图类型化签名、属性名、事件触发值；不给频次、参考查询或参考结果 |
| 目录能力 | 六服务没有按时间检索 Issue／PR 生命周期或计算这些比值的操作；属于范围外诊断 |

本试验选题依据是参考可核验性，不是代表性。用它检查“图可回答但目录不能表达”时的能力拒绝与错误接纳；不拿它作为主任务分布或预设服务总体劣势。正确拒绝与完成任务分别计分。E1/E3 的提示信息和任务范围不同，不能直接相减作为方法增益。

预测前冻结源码、任务摘要、共享 schema、数据库身份与参考检查。在线结果在阶段完成后追加；完整独立工作负载仍需其余来源定义、去重与参考。
