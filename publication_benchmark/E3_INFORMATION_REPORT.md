# E3b：服务输出是否足以支持上层任务

分支：`codex/ch7-e3-information-boundary`，依赖 E3 预测前版本 `5ef0c0c`。见证执行代码冻结在 `d3ec965`。本阶段无模型调用，不修改正在运行的 E3 源码，也不修改真实项目数据。

## 配对世界实验完成

建立两个明确标注为合成的图，各 7 节点、6 边。节点、关系与实体身份相同；唯一干预是 `Issue I_900001#1` 的 OPENED_BY 边的 `source_event_time`：

| 检查项 | 世界 A | 世界 B |
|---|---|---|
| 被干预 Issue 的打开时间 | 2023-07-04 | 2023-08-04 |
| 六类服务的 67 组合法调用 | 与 B 相同 | 与 A 相同 |
| 七月观察到的新增 Issue 数 | 1 | 0 |

先用独立 CSV 函数核验，再导入两个新建专用数据库，执行全部编译 Cypher：每世界 67/67 服务调用匹配参考，且跨世界输出多重集合相同。独立目标查询分别得到 1 与 0。保存数据库身份、CSV 摘要、编译器摘要和原始执行记录。

## 为什么出现信息损失

| 现有服务 | 相关依赖 | 能否观察本次改变 |
|---|---|---|
| issue_openers | Issue ID、OPENED_BY、Actor ID；返回 Actor ID | 不能，未读取或返回打开时间 |
| issue_count | Issue 身份与前缀 | 不能 |
| issue_commit_path_count | COMMENTED_ON_ISSUE 与 REFERENCES 路径 | 不能，干预的是 OPENED_BY 时间 |
| pr_links | PR 到 ExternalResource 的链接与字段 | 不能 |
| pr_domain_counts | PR 引用的时间、域与计数粒度 | 不能，干预不涉及这些引用 |
| pr_link_count | PR 引用的时间与粒度 | 不能 |

67 组有限执行不是所有参数的穷尽证明；上表对冻结编译器依赖的检查解释了为什么改变这种边上的时间不会影响任一现有服务参数化查询。该反例只针对当前六服务接口，不针对所有受控接口。

在“用户上下文相同，且上层只访问这六类服务、没有额外图／API 信息”的条件下，上层得到同样的观察，却需要输出两个不同答案。因此，单靠增加角色或更换上层模型不能恢复这个缺失信息。如果用户上下文或其他数据通道提供了时间，条件就已改变，不能套用此结论。

## 对主线的作用

这不推翻 E1/E2 共同能力交集上的结果。它限制“现有基础服务加上自然语言交互就能完成更复杂任务”的扩大声明。

下一实现候选应先解决任务所需信息：增加受控时间过滤参数，或返回带事件时间、实体和证据标识的事实行，再做明确的筛选／聚合。不能先丢掉时间，再要求上层猜测时间条件下的结果。新接口与拒绝策略必须另立版本，并复查旧任务，不能回改 E3 v1 的结果。

这是一项接口充分性反例和工程约束，不是新的通用信息论定理，也不是实际用户错误率。它本身不能证明可录用的贡献；后续需在有来源的任务和留出项目上验证覆盖、错误接纳与成本折中。
