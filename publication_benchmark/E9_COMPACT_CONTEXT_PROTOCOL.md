# Representation-appropriate context control

Predeclare before reading new blind-generated requests or independent predictions. Redis full-context development showed equal G/I task correctness and only a 551-token total difference (88,773 vs 88,222 across 14 tasks). That is not a stable cost advantage. Both arms had unnecessary representation-specific material: G saw service calls/catalogs and I saw unused graph-storage metadata. Avoid claiming lower cost based on an unnecessarily verbose opponent.

Compact G keeps every node label/property, physical/service typed signature, raw trigger value and interpretation from the shared schema. Deduplicate common node properties; remove unusable service catalog/call examples and retain only the paired direct query examples. Compact I/P keep their complete executable contracts and only the paired service examples, without graph-storage metadata or Cypher examples they cannot execute. Snapshot/business constraints and observed-event meanings remain explicit for all arms. I/P use the same output/refusal instructions as before. No compiler, service semantics, answer, repair budget or model setting changes.

First check the compact variant on the same 14 known Redis development tasks; retain full-context E6 results. This is a declared representation/context control, not a causal proof that the architecture is universally cheaper. Then freeze the chosen contexts before new task predictions; do not tune after inspecting them. Use the compact direct arm as a stronger practical cost baseline if evaluating service costs. Report coverage losses and wrong returned answers as well as tokens; outputs only and successful calls only are incomplete cost measures. Provider prices/remote unknown usage remain unknown.

Runtime command adds --context compact. The immutable manifest identifies actual context variant, actual catalogs and renderer hash. A copy of all source files and the complete request payloads is preserved. Existing E6 full runs are unchanged; both context variants remain separately labeled. Matching eventual correct outputs at high development accuracy does not establish formal noninferiority.
