# Text2GQL 有界执行与持久请求验收（开发阶段）

本阶段完成原生执行基础件，不是正式预测准入。方法仍称 Ours；原 CypherBench 全量数字、负结果和冻结版本不改。

## 已完成

新增 `tugraph_execution.py`，版本 `native-execution-dev-2`。Direct 的一般只读 Cypher 与 Ours 编译出的有限计划共用执行日志。每条查询先做词法检查，再对相同图/脚本做原生 EXPLAIN；只有原生 `@plan` 的 `ReadOnly:1` 计划才能进入执行。EXPLAIN 与查询都计入物理数据库次数、时间和原始响应字节。固定图快照和只读身份/服务所有权仍由外层准入控制。

请求 ID、原始脚本、图和资源参数须一致。派发前独占创建目录，写入请求与预留记录并 fsync；之后保存原始响应、哈希、HTTP 状态、传输/执行完整性、时间、成本未知字段及结果封印。已完成请求只在证据哈希一致时回放，新增请求数为零；未完成、未知或内容变化须审计，不能自动重发。进程异常/写盘失败不删除证据目录。

私有 HTTP 适配仅访问指定 IPv4 回环端口，不使用代理、重定向或自动重试。查询时限与总传输时限分开，逐次设置剩余读取时间；按共同64MiB/百万行边界拒绝不完整结果。达到边界、截断、未知、畸形 JSON 和合法空答案分开保存。数据库超时后的实际终止、外层总SQL/路径预算、驻留内存监督仍须在正式 runner 集成验收，不能凭客户端时限承诺服务端硬资源隔离。

反馈 builder 仅接受明确语义/编译诊断，且已有反馈次数非零时不再生成。成功返回（含错误答案和空答案）不按 gold 触发修复。基础设施/未知/畸形传输不当成模型语义错误；模型调用账本与持久的一次反馈派发控制尚未接入，本阶段没有发送反馈或模型请求。`execute_native_plan` 保留底层未知状态与成本，不自动回退 Direct。

## 实测与保留的失败

仅使用既有四实体四边独立开发图及手写输出，未读 benchmark TEST 问题/答案或模型私有配置。本轮35次原生请求全部保留：

| 作业 | 物理请求 | 结果 |
|---|---:|---|
| EXPLAIN 能力探测 | 3 | 三条均返回只读执行计划 |
| 初版集成 | 7 | 前4个记录符合预期；第5个错误格式分类失败，停止；剩余未派发 |
| 修复后相同8个检查 | 15 | 8/8；包括同ID缓存回放零新请求 |
| 最终有限计划桥接 | 10 | 3/3：单选择、摘要策略和全明细策略 |

初版实际解析错误为 `[ParserException] ParserException: ...`，分类器只识别无括号格式，误记为基础设施错误，导致非 gold 反馈不可用。修复为显式异常类型前缀识别，未知 HTTP500 仍保守归基础设施错误。原始失败、旧源码和响应均保留；修复版原检查/预期不变，不把复测和共享计划当独立任务或 EX。

76项本地检查通过（原59项加本阶段17项）。覆盖并发同ID、进程中断遗留、原始响应篡改、部分/短Content-Length传输、只读未确认、服务错误/未知、上限、反馈次数、有效空/错误答案、计划失败保真等。故障注入明确为合成检查，不冒充真实线上故障率。桥接实测使用的执行模块哈希与最终源码一致。

四个私有作业的服务均已退出；授权 hostname/owner匹配，主锁不存在，18880–18883无监听，无相关原生进程。没有清旧锁、重启服务、训练或占GPU。未重跑任何旧一次性作业。原冻结32源码哈希一致。
