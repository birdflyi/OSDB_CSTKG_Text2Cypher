# OSDB 开发后台接续 v2

v1 完成 Redis 的 12 条方法路径、16 次物理调用后停止。全部请求 HTTP 200，其中三次 `finish_reason=length` 且最终 `content=null`，旧信封校验误将其归类为基础设施失败。原始请求、响应、评分、冻结和成本保持原样，另存归类审计旁证。

v2 仅允许上述 length/null 信封进入已有 `MODEL_TRUNCATED` 分支；不执行查询，不计正确，不增加输出上限，不增加反馈机会。stop/null 仍作为无效信封处理。三项离线检查覆盖归类、禁止截断后执行及跳过已完成的 Redis 全图。

新入口 `run_osdb_background_continuation_v2_20261027.py` 固定原消息、方法、采样、参考和批准用途，校验旧 12 路径及旧事后报告的 SHA。只派发尚未发出的 DuckDB、IoTDB、Elasticsearch 共 36 条首轮路径；每路径最多一次既定操作反馈。全局上限仍 64，本批最多 12 路，自动传输重试为零。连续三次实际基础设施失败停止新派发并排空。

新冻结目录与旧执行目录分开。后台自动逐图验收、运行、关闭，然后自动评分与成本对账。累计开发摘要链接两个冻结版本，并拒绝重复路径；旧结果不改写，也不冒充独立正式验证或整张 T1 完成。

监控仍用节点自有 tmux 双中文窗口；读取快照，不调用模型。启动前核验自有目录和两个 pane，其他服务不动。未知请求禁止重发。
