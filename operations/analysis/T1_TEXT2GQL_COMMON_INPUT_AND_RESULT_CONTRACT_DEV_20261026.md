# Text2GQL 共同输入与原生答案表示：离线准备验收

2026-10-26。这是 T1 新结果块的准备，不是正式预测或主指标冻结；本轮没有模型或数据库查询。

## 共同输入已接通的部分

新增纯函数模块 `tugraph_common_input.py`。它不读取模型配置，不发请求，只接受明确的任务 ID、图名、问题、schema 和候选列表。

- Direct 与 Ours 的 user message 使用**完全相同的序列化字节**，包含实际 schema、原生主键、同一实体候选及同一方言说明。各自只增加不同输出形式的 system 指令：Cypher 或有限服务计划。
- 方言说明同时披露已确认的原生行为：显式变量 WITH、全局 OPTIONAL 条件、NULL 否定、实体计数、时间字面量。Direct 允许引擎支持的一般只读查询，不人为限制为 Ours 的有限 IR。
- Ours 指令使用真实主键和实际属性，不再携带旧 Neo4j 提示中虚构的 eid/rid/aliases/name 元数据。
- 候选来自已导入的顶点 CSV 的声明主键和 STRING 属性，固定最多 12 项，保留同名多实体和原始类型；没有读取参考查询、答案、difficulty 或 source，也不静默改写问题。
- 六图 **21,315 个实体**全部进入可追溯目录，按实体类计数与导入验收一致；配置和 CSV SHA 均匹配既有输入计划。六组构造开发问题的 Direct/Ours 输入字节一致。它们不是 benchmark 测试问题，也没有生成预测。

这种简单词项候选器只用于共同输入公平性，不是具名实体链接方法，也没有实体链接准确率或优势结论。目录构造与查询时间单列为准备成本，不能当正式 T4 性能结果。

## 答案表示检查已完成的部分

新增 `tugraph_results.py`，按原始 UTF-8 JSON 验证响应结构、行宽、报告行数、嵌套值及共享资源上限。不根据 header 的 type=0 猜测实际类型，不把日期字符串强转成伪数据库时间对象。

调用方必须分别确认传输完整和数据库执行完整；HTTP 正常结束本身不够。不完整、达到资源上限、错误响应和畸形 JSON 不作为正确空答案。

独立的严格比较函数仅作**类型、重复行和排序敏感性诊断**：区分 bool/int/float/string/null，保留多重集，不靠 Python 的 True==1、数值取整或查询输出决定排序检查。它不是作者 EA，也没有被选为主指标。

对既有六图参考审计的原始缓存响应，仅做了表示验证：

| 检查对象 | 数量 | 本轮结果 |
|---|---:|---|
| 已有成功参考响应 | 3,815 | 行形/类型结构检查通过；包括 1 个合法空结果 |
| 已有参考执行错误 | 11 | 均未被解析成成功或空答案 |
| 新数据库查询 | 0 | 没有重跑参考或开发查询 |
| 新模型调用 | 0 | 没有预测或接口探测 |

这不是重新验证答案语义，也不是 3,815 题模型答对。参考响应只进入表示验证分支，没有进入候选构建、模型输入或方法适配。输入分支只用 schema 与图数据，未读 TEST 问题 JSON。

新增组件 15 项检查通过；加原有回归共 **59 项**通过。原 CypherBench 的 32 个冻结源码哈希保持不变。
