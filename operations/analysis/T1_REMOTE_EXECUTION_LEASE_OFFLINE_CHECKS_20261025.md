## 我们检查了什么

| 故障或风险 | 检查结果 |
|---|---|
| 第二个进程取得执行权 | 已有锁时拒绝；子进程异常退出后仍保留锁 |
| 旧本机 runner 同时派发 | 候选执行锁与原 AttemptBudget 的锁路径兼容；原 reserve 被阻止 |
| 新账本把用量归零 | 合成 3,266 条历史基线后，首个新槽位为 3,267 |
| 一个请求结果未知 | 保留 pending，阻止下一请求；不自动重发 |
| 超时后重试不计费 | 每次物理尝试占一个新槽位；失败也占用额度 |
| 到达累计上限 | 拒绝额外尝试；不是按新片段重新给 12,000 次 |
| 账本缺号、基线或请求被修改 | 拒绝继续 |
| 审批文件被修改 | 不自动提高额度，要求重新核验 |
| 请求来自错误目录 | 拒绝预留 |
| 原调用器连续三次超时 | 三次均入账，要求两次 10 秒等待，随后停止；第四次不会发送 |
| 未完成远端回收就释放锁 | 拒绝；需独立固定哈希的完成及对账证据 |

测试中的发送函数和等待函数均为替身，没有打开网络连接。等待参数检查不等于实际网络重试或真实 10 秒计时验收。合成历史不是实际额度分配。真实账本只读核验，未创建真实执行锁或历史封存文件。

代码在独立恢复分支的 operations/leased_attempt_fragment.py 与 test_leased_attempt_fragment.py。真实冻结驱动尚未导入这些候选模块。当前正式运行版本没有改变。
