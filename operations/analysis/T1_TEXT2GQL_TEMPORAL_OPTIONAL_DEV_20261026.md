# Text2GQL 日期时间、布尔与 OPTIONAL 适配验收

2026-10-26。本轮是 T1 离线实现准备，没有模型调用、正式预测或主表 EX。原 CypherBench 源码、预测及结果不变。

## 完成的实现

开发版本为 `typed-services-dev-0.7-native-optional-projection`，沿独立分支 `codex/ch7-t1-tugraph-adapter` 推进。

- **DATETIME**：接受无时区 ISO 时间，0–6 位小数，保留微秒；编译为原生接受的空格分隔格式。拒绝时区猜测、丢弃偏移及更高精度截断。仅改变类型字面量编码，不改数据或参考查询。
- **BOOL**：只接受真正布尔值及布尔成员列表，支持等于、不等于、成员与 NULL 检查；不把整数、字符串当布尔值。原 Neo4j 默认路径未扩展这些新字面量。
- **一个受限 OPTIONAL**：保留原 IR 的边数与语言边界。必需匹配后用显式变量 `WITH` 开新查询阶段；全局条件放在 OPTIONAL 后。过滤时仅携带需要的节点及边属性标量，保留重复行；不传递不需要的可空边对象。
- 可空节点计数采用非空主键属性，零关联实体计为 0；实体分组仍依实际主键，相同显示名称不合并。必需匹配与 OPTIONAL 属不同匹配阶段，允许后者复用前者的物理边。

本轮没有依赖 TEST 问题或模型结果修改方法。两套预期均在各自第一次查询前固定。OPTIONAL 前后两版的 18 个 selection、ID 和预期答案完全一致。

## 实际验收与失败保留

| 阶段 | 固定检查 | 额外诊断 | 结论 |
|---|---:|---:|---|
| 新建独立 BOOL/DATETIME 小图 | **20/20** | 2 条 | 微秒包含/排除边界、补零、日期绑定、NULL、布尔 JSON 类型通过 |
| OPTIONAL 查询阶段探测 | 不设效果分母 | 6 条，4 条符合预期 | 显式变量 WITH 可用；WITH * 两条报未实现 |
| OPTIONAL 编译 v1 | **12/18** | 0 | 六条全局过滤遇到 RealConsume 未实现，全部保留 |
| OPTIONAL 投影诊断 | 不设效果分母 | 5 条，全部符合预期 | 节点/标量投影可用，无需改变参考答案或用简化问题替代 |
| OPTIONAL 编译 v2 | **18/18** | 4 条，全部符合预期 | 全局过滤、可空边属性过滤/聚合/载荷均通过 |

日期时间检查包含 `.123455`、`.123456` 的一微秒差、`>` 与 `>=`、`T` 转空格及短小数补零，未增加结果容差。布尔返回用类型敏感的 JSON 比较，不能靠 Python 的 `True == 1` 掩盖类型差异。

OPTIONAL 检查包含零邻居、同名不同主键、按显示值分组、全局 NULL/否定、锚点与后续边复用、已绑定两端点、反向边、空自环、重复载荷、空必需集合、显式 LIMIT。原先六项失败是原生执行器未实现相应投影路径，不是模型接口或 SSH 基础设施失败，不能计为模型不正确或隐藏重试。

另有一个模式推导式诊断仍报未实现，不作为降低路径。固定源码也明确标记 PatternComprehension 未实现。当前实现使用实际验证通过的显式变量阶段与标量投影。

本轮新增原生查询 **73 次**，包含全部失败和诊断，无自动重试；接受的最终固定检查是时间/布尔 20 项与 OPTIONAL 18 项，不能将重复开发执行包装成更多独立任务。

当前版本对旧 20 项时间/布尔调用生成完全相同的查询与参数。旧集合服务 8 计划×2策略还进行了 **16 个离线响应回放**：先核对全部 32 个查询、参数、脚本和原始响应 SHA 一致，再核对最终结果；回放不是新增数据库执行或模型预测。

44 项本地检查通过。首次本地开发曾因 Python 3.9 不接受一位小数字符串而出现 1 项解析错误；在执行原生检查前，以不丢精度的右侧补零修复，原预期未变。

## 正式预测前仍缺什么

1. 同等 Direct/Ours schema、主键/实体信息、方言说明、输出及反馈权限，并完成 TRAIN/独立开发的模型验证。
2. REST/Bolt 答案表示和作者评分/子集协议：本小图 REST 的 DATE/DATETIME 返回字符串，不能据此宣称已复现作者 Bolt 口径；header 的类型值也不足以推断全部实际类型。
3. 全量 3,826 题与 11 条未知参考的处理、固定统计分组、资源限制、完整成本及正式冻结。
4. Text2GQL 新增 20,000 次调用申请仍待明确回复。累计仍 **5,192/12,000**，剩余 **6,808** 限原 CypherBench 范围；本轮新增模型调用 **0**。

这一步提高实现可用性，不证明 Ours 的模型效果或成本优势，也不改变原 CypherBench 未确认显著 EX 收益的结论。整张 T1、具名方法及其他必要结果块仍未完成。

本轮仅操作私有 CPU 回环服务，全部子进程退出；授权 hostname/owner、无主锁、无相关原生进程及 18875–18879 无监听均已核对。旧 GPU/模型/系统服务和旧锁未改，接续调度器未改，T2–T5 未启动。
