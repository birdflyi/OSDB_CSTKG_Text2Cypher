# OSDB 共同输入与共享只读执行器开发验收

24个原开发题位已准备新版共同输入，双方用户消息逐字节相同；共享执行器已在新建的Neo4j 5.15.0隔离小图完成真实Bolt验收。**四个真实图尚未建立并验收语义专用副本，因此这不是OSDB正式准入或主表EX。整张T1仍未完成。**

这一步解决“提示里隐藏导入元数据，但Direct实际上仍能读到”的问题。方案要求物理图只含声明的语义标签/属性/关系，不把正则禁止某个属性名当成权限隔离。执行器先全图扫描，检查标签、属性类型、主键唯一性、关系签名，并生成含全部属性、端点和物理边的指纹。小图指纹与固定夹具独立计算的指纹一致。存在PilotNode标签或__pilot_uid属性时，准入失败，Direct与编译方法都不能派发查询。

准入后双方共用已有只读词法检查、真实Bolt EXPLAIN的query_type=r校验、实际执行及相同结果上限：最多100万行、64MiB行数组、5万查询字符；EXPLAIN/查询事务超时分别30/60秒，不追加隐式LIMIT。240秒全图准入扫描属于离线环境核验预算。原生Direct保留UNION、只读子查询、聚合和属性映射，没有被压到Ours的有限计划接口。超限明确返回TRUNCATED/complete=false，编译方法不能把该结果当完整证据。

这是基于**独占且不变快照**的客户端执行政策，不是Neo4j Community的RBAC或网络安全边界；外部特权进程仍不应访问该快照。返回完整图对象的最终标准化、任务评分和反馈合同仍须另验。
