# OSDB 持久SSH接续 v3

v2 在 DuckDB 12 条首轮请求中有一条 SSH 返回255（Connection closed），其余11条模型请求HTTP200。未知保护停止新派发并排空。远端自有目录审计确认该条请求目录/claim不存在，节点worker全部结束；节点worker必先落目录与claim再发HTTP，故另存审计终结，无重发。原28个预约槽全部保留；费用/usage未知不补零，旧输出、posthoc、scope_close不改写。只释放经PID/lease/原始字节核对、已退出排空并完成审计的自有许可锁。

节点sshd报告maxstartups=10:30:100，12条新连接同时握手可能触发丢弃，但没有服务端丢弃日志，不能断言唯一原因。新传输在模型预约前串行建立两条已认证SSH连接，每条最多6个通道，复用原one-shot worker和未知收据规则。禁止自动重连、传输重试；主机密钥严格校验，其他服务和sshd配置不改。

两项合成检查通过；真实2连接×12通道只读hostname检查全部通过，不消耗模型或DB。新运行时冻结Paramiko及加密依赖版本。后续模型使用用户指定louzehua私有配置，凭据和实际批准文件不入Git，旧配置保留。

v3仅运行IoTDB→Elasticsearch尚未派发24条路径，保留Redis12与DuckDB11原终结及1条审计基础设施失败；失败不算正确，也不混成生成答案。最多每路径一次既定操作反馈，无训练/额外探测。原48消息、模型采样、8192输出上限、240秒模型/30秒EXPLAIN/60秒方法读取/600秒离线扫描不变。实际最多12路，全局64硬上限。

自动事后报告分版本计费去重，累计开发摘要显式链接三个冻结和失败审计。未知方法耗时不计入分布且单列数量。旧开发题不冒充独立验证，算法增量未成立、其他T1必要格及T2–T5保留。
