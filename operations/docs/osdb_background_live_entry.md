# Continuous OSDB exposed-development entry

`analysis/run_osdb_background_live_20261027.py prepare` creates a new immutable development bundle and an owned node deployment. `run` is executed from that bundle as a detached, hidden local process. It traverses four graph contexts automatically, drains each graph's futures before closing, then joins raw answers and the cumulative budget for posthoc scoring. There is no old-run resume or logical request resend.

The entry uses the accepted local graph factory, a central shared model permit lease (12 ready paths, human global ceiling 64), and the separately approved 96-attempt OSDB scope. The 48 initial message files remain unchanged. One operational repair at most is allowed per path; there are no transport retries or additional model probes. A real developer request is the first long-context observation. It is not a formal prediction or a second-backbone result.

Model calls originate on the authorized node using its existing private configuration and owned relay. The worker embeds the exact previously accepted one-shot HTTP class, validates its source, owner, allowed logical ID, private configuration hash and sampling, exclusively claims each request, and saves raw bytes plus terminal evidence before returning an ASCII-safe envelope. SSH timeout, failed receipt or unknown remote outcome leaves a pending local attempt and retains the central dispatch lock; it does not become an invitation to resend. Credentials are not copied into this repository or the local bundle.

Final method outcomes are saved before controls. The new isolated cost path retains the old full-detail replay and simple-policy alias, then runs the scope-eligible same-plan native set-count control with a separate cost root. Unsupported control shapes are explicitly not applicable, with no extra model call and no change to the model denominator. Method time excludes both control replays. The original frozen methods and prior cost/dispatch modules remain unchanged.

Seven new synthetic wiring checks passed: exact worker-class preservation, UTF-8 raw receipt round trip, SSH timeout classification, scoped pending/central-lock retention, native cost separation, native not-applicable handling, and a centrally guarded two-path dispatch/drain. The dispatch fixture initially used a DB-counter stop that legitimately allowed a third path to fill an available slot; its failed version is preserved and the fixture stop is now tied deterministically to the second synthetic transport. An entry import error before preparation is also preserved. None of these checks used a real model or database. Previously passed checks and real graph acceptance were not replayed.

The development freeze pins source closure, adapter guard files, approved message/evaluator hashes, model configuration, graph inventory/profile hashes, Python executable, package versions and engine JAR. Posthoc scoring runs only after the scope closes; numerical references and unscored boundary positions stay separate. Full deployment independence, formal task scope and algorithmic increment are not established by this entry.

Monitoring is file based and asynchronous: a publisher sends at most one compact node snapshot per 15 seconds, while the two Chinese Rich views refresh every three seconds. It never sends provider probes, computes per-token statistics or holds model/database permits. The existing two owned tmux panes can be repointed after their start commands and ownership are verified. Display errors do not stop generation. The durable background plan, raw attempt folders, graph receipts, posthoc report and issue JSONL are the execution evidence; a tmux pane alone is not a runner.
