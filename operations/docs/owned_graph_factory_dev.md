# Owned graph factory for OSDB development

`analysis/osdb_owned_graph_factory_dev.py` supplies the graph context expected by the cost-separated development dispatcher. It starts one new local Neo4j copy at a time. It does not import data, start original stores, call a model, resume a campaign, clear old locks or manage remote services.

Before boot, it checks the pinned inventory, profile and cold manifest hashes, hashes the actual source store files, copies them to a new directory, then verifies the copied bytes. After boot, the shared model-read executor scans every physical node and edge and checks the resulting fingerprint and counts against the accepted semantic snapshot. Both methods receive the same schema and executor; this is an implementation property, not a claim that either model has already run.

The exclusive factory lock is separate from the central model gate and model budget lease. An existing lock is preserved. New directories and receipts use exclusive creation. Each graph can be opened only once by an instance, and the context remains open until the dispatcher's submitted paths drain. Uncertain ownership or cleanup retains the factory lock for audit. Source bytes are checked again after use, without booting the source. A source which fails initial verification is not incorrectly treated as a later mutation during cleanup; the first preflight failure and executed sources remain in the v1 evidence folder.

Full physical admission scans have a 600-second server transaction limit, matching the previously audited Elasticsearch offline recovery budget. This is data admission, separate from method EXPLAIN (30 seconds) and execution (60 seconds). The client also has a 1240-second admission-call deadline and 100-second answer-call deadline. A watchdog interrupts the known driver's I/O by stopping only its verified owned JVM. This is not a sandbox for arbitrary Python callbacks. Deadline failure invalidates the graph and is retained as infrastructure evidence, with no statement replay. Unknown transport outcomes are not silently converted into query correctness failures.

Shutdown verifies the exact owned child configuration before stopping a JVM; it never searches for and kills arbitrary Java services. HTTP and Bolt listen on loopback. The factory exports a non-I/O physical statement counter for the independent cost recorder. Client walls include driver, EXPLAIN, normalization and evidence writes; they are not pure server compute. Fixed heap/page cache and two active processors constrain this local runtime. Formal resource, timing, quality and task admission are separate.

The finite acceptance entry `analysis/accept_osdb_owned_graph_factory_20261027.py` is versioned through its new evidence directory. It checks four real snapshots with one count read each through the new factory and one deliberate client deadline fault on the last owned graph. The fault is not a method result. The evidence pins executed source bytes, profiles, inventory, original frozen source hashes, budget and shutdown receipts. No model messages, references or model budget approvals are changed. Passing it does not itself launch the 48 development paths or accept formal T1.
