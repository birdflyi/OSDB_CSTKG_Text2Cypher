# Operational approval records

- Keep one-time human runtime approvals local, normally in the task's state/reports folders. Do not copy or force-add ignored approval JSON into publication Git; publish a non-sensitive protocol summary when needed.
- Never commit actual passwords, API tokens or private-key contents.
- User clarification: an internal hostname or a key-file path alone is not an authentication credential. Do not remove otherwise useful code merely because it contains an internal machine identifier.
- Preserve active and frozen source bytes. Review the staged diff before committing or pushing. Do not rewrite pushed history as a routine response to a scanner notice.
