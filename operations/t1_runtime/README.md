# T1 中文监控与并发容量验收

这是独立的运维开发组件，不修改原CypherBench冻结源码/预测/评分，不训练模型，不访问图数据库或管理其他服务。模型请求执行在授权Linux节点；本机仍为原预算账本权威，通过只绑定loopback的SSH反向通道确认每次预留并接收终结证据。当前实现依赖本机预算协调器和SSH通道存活，不宣称脱离本机的全远端无人值守执行。

## 两个中文窗口

在部署节点上执行：

```sh
tmux -L ch7-t1-monitor attach -t ch7-t1
```

- `Ctrl+b`，然后`0`：全局流水线。
- `Ctrl+b`，然后`1`：逐题监控。
- `Ctrl+b`，然后`d`：断开看板，实验继续。

`ch7-t1-global`和`ch7-t1-detail`是同组窗口的独立查看会话，允许两个客户端分别固定在全局/逐题窗口。使用任务专属tmux socket，创建/更新前核对新/旧目录execution_owner及每个pane的启动命令；只替换本任务已证明归属的两个监控进程，不接触默认tmux服务器、其他进程或GPU/模型/图服务。

监控仅读取小JSON快照，3秒刷新一次，分位数最多每30秒更新；最近1分钟/5分钟使用内存增量窗口。阶段尚不足窗口长度时按已经运行的时长折算并标明，预热样本不足不估ETA。端点全负载和排队没有遥测时显示未知；我方token/s是已完成usage推算，不是瞬时GPU解码率。关闭/崩溃/渲染错误不控制任务派发。

全局清单含已完成的原DeepSeek核心、其他候选及作者资源缺项。当前实接的是TRAIN容量验收；其他基准/作者方法仍受各自冻结、图/评分/权限与预算准入约束，显示“准备中”不表示已启动。后续执行器可沿相同`state.json`协议更新任务清单和事件，不将预览或资源测试填入正式EX。

## 并发与预算

- `parallel_budget.py`在原`.t1-reservation.lock`上取得本轮排他租约，开始/结束各完整核验一次；租约内每次预留为O(1)，写入原连续编号槽并保存请求SHA，原冻结模块不改。
- 请求ID在本轮幂等：同ID同请求返回原槽，不重复计费；请求/终结冲突拒绝。未知终结保留pending，后续租约不能启动。释放时验证锁字节仍是本轮owner，不能清理别人的锁。
- 远端获得本机预留确认后才发模型POST，响应先在远端不可变落盘，再送回本机原请求旁的terminal。通道中断不盲目重发模型请求；模型没有自动重试。控制确认可做至多3次幂等交付，不产生额外模型调用。
- 固定12条已暴露CypherBench TRAIN任务的Direct/Ours首轮提示，共24种输入，不读取gold/测试题，不执行图查询，不做新方法准确率主张。每次trial带唯一测量ID。
- 逐档16/32/64/128，必要时48细测；同端点共用全局池，不按任务倍增并发。已有通过的串行基线和16档通过明确SHA引用复用，原失败/部分结果不覆盖。
- 初始每阶段最多240秒继续派发，随后等待已在途请求终结；128档首轮499条不足预定四波512条，单独确认轮预先固定512条、360秒派发窗，原499条和成本保留。连接10秒、网络读取240秒、响应体4MiB上限。同体只发1次（低于既有最多3次），连续3次基础设施失败停批，非重试鉴权错误立即停批。
- 输出使用用户提供3500 token/s估计调速；实际usage返回后校正预计扣账。信用容量至少8192以容纳单请求上限，防止大请求永远等不到足够信用。该策略不能保证服务端瞬时QoS或证明后端最大吞吐。
- 候选甜点同时保存整批case/min和客观中段窗口：完成序列两端各去一并发波的启动/排空边界，在中段计算完整响应速率。原分母、全部失败/截断、全批耗时和全部成本均保留，不按结果删样本。低于4波不评稳态；增加并发收益不足5%停止加压。
- 阶段派发窗是有意调速和等待的共同上限；已超过派发窗后的正常排空不判成调度失败。看板部署失败单独记录，实验协调器继续；整个容量批另设总期限，超时只终止本协调器的SSH子进程，未知请求保留待审计，不自动重启。
- 推荐为观测最高持续完整响应吞吐95%以内的最小请求上限，候选需HTTP200>=99%、完整响应>=95%，这不是准确率阈值或论文指标。模型截断单列，不能说已完成正式查询。服务负载/缓存/任务随机生成变化仍限制外推。
- 达到128档仍有收益，只能称“已测范围内的推荐上限”，不能声称已经找到服务饱和点；不自动越过用户授权去测256。旧64档调度停止标记原样保留，中段和整批数字同时列出。

## 运行入口与验证

协调器需要本地私有node配置、私有模型配置和一个不存在的新输出目录；配置与操作审批只留本地，不加入Git。不要对已经运行/停止过的输出目录直接重跑。

```text
python coordinator.py --node-config <local-private-node.json> --model-config <local-private-model.json> --output <new-local-report-dir>
python -m unittest test_runtime -v
```

`monitor.py --state <snapshot> --view pipeline|job --once`导出静态文字；`--html <path>`导出可审阅HTML；`--benchmark`用30帧测量纯CPU渲染开销，不发网络/模型请求。原始问题、响应、逐trial日志只留证据目录；公开只发布自有代码和聚合报告。

容量验收期间有合法在途pending是正常状态，必须结合本轮owner、协调器PID、远端进程与新鲜心跳判断，不能清锁或另派一批。节点/通道改变需保留旧日志并先证实具体修复，不靠开新批次绕过失败停止。
