# 独立实验流水线

这是一条普通的 Python 流水线。启动后，领取许可、派发、重试、保存、切图和切换方法均由程序完成，不需要聊天代理逐批放行。聊天额度用尽不影响已启动的子进程。机器断电、进程被杀或真实服务下线仍会影响执行；程序不会伪装这些状态为正常运行。

## 执行顺序

1. 校验一次源码、输入、模型、预算、数据和执行准入；禁止启动第二个账本写入者。
2. 在打开数据库前，把全部已准入 method×benchmark 的首轮请求写入 `prepared_queue.jsonl`，包括原始请求体、逻辑身份和 SHA256。未准入的结果块写明缺项，不发送。
3. 对当前 method×benchmark，先生成和保存所有图的首轮模型回复，再依固定顺序执行数据库、必要的一次操作反馈、控制和评分。已有效返回的回复从完整历史账本复用，不重复生成。当前方法完成后自动进入下一方法。
4. 每个请求独立领取同模型端点许可。端点可动态加入、禁用或调整上限；禁止不同模型互相代答。

反馈只能由真实的非参考执行错误产生。因此，首轮请求可以全部提前准备，反馈请求不能凭空提前生成。它们在发送前写入 `feedback_queue/`，仍受同一总池、预算和重试规则约束。

## 当前候选派发规则

容量来自具体端点配置，没有写死的并发上限。当前新DeepSeek端点配置为32；这仍不是在线容量验收结论。程序要求显式提供全局容量，同时遵守各端点容量。

```json
{
  "global_cap": 32,
  "batch_size": 8,
  "batch_interval_seconds": 0,
  "prefetch_initial": true,
  "queue_wait_until_available": true,
  "continue_on_path_failures": true,
  "retry": {
    "max_attempts": 3,
    "wait_seconds": 10,
    "before_write_only": false,
    "retry_unknown": true
  }
}
```

- 当前采用滚动补位，不人为增加批次等待；上一批尚未返回也可继续派发。实际在途受全局和各端点容量共同约束。如果服务另有速率限制，才显式配置批次间隔。
- 500、连接失败、超时等传输/资源问题触发当前端点的一次减半，单请求响应超时翻倍。当前32→16、240秒→480秒。一次恢复周期内不反复减半，也不把超时继续翻倍；已有在途请求自然排空，不取消。
- 只有在恢复状态下新领取许可的请求连续3次通信成功，才恢复该端点当前配置的容量和基础超时；失败重新计算连续成功数，其他端点不受影响。旧的在途请求不能提前认证恢复。端点容量变更后，减半值和恢复目标随新配置更新。
- 通信成功与题目答对分开。查询、输出解析和评分坏case不触发端点降并发；它们记录到对应路径，并继续其他任务。
- 失败请求延后至少10秒再进入许可队列；等待重试不占HTTP连接或模型许可，其他就绪任务继续。跨版本同体最多3次，未知及失败都计入批准额度；有效回复不重发。
- 429遵守服务端 Retry-After；普通传输失败不再触发旧的长时间隔离。模型身份不符会阻断该错误路由。没有健康检查、占位请求或隐藏SDK重试。已确认被回收的端点应禁用。
- 领取许可超时是排队事件，不是一次模型调用。启用持续排队后，程序继续等真实容量恢复，不再因这一点结束方法、消耗尝试号或需要聊天代理重新放行。
- 已删除旧 `RecoveryGate` 和相关恢复容量参数，容量与恢复统一归 `DynamicPool` 管理。`BatchPacer`只负责显式配置的发送间隔，不再自己执行另一套故障缩容。

## 失败与停止

普通传输失败按上述规则自动处理。穷尽尝试后保留失败；普通路径、数据库执行、反馈构造和阶段异常分别留档，其他就绪任务及下一独立任务块继续。评分失败保留该行、记录`score=null`，不冒充答错或答对；其余题目和图继续。含工程坏case的块写 `incomplete.json`，不能标成完整成功。

预算耗尽、手工DRAIN、冻结/归属不符、持久化失败、未终结已计费请求等属于需要明确处理的错误。`IntegrityError`和`PersistenceError`与普通case异常区分；程序排空已发送请求并留下问题记录，不无限重启、不删除失败、不擅自换模型。已终结的incomplete块重启后保持缺项并跳到后续任务，不重新发模型；突然断电或被杀后的未知请求仍须先核验账本，尚未实现所有崩溃情形的全自动恢复。

## 日志与结果

| 文件 | 内容 |
| --- | --- |
| `launch.json`、`stdout.log`、`stderr.log` | 独立进程PID、命令摘要、启动时间和异常输出 |
| `prepared_queue.jsonl`、各阶段`queue.jsonl` | 已冻结的完整首轮请求字节与逻辑身份；准备清单不等于实际派发数 |
| `journal.jsonl` | 派发意图、实际进入发送、重试预约、排队延后和终结事件 |
| `attempts/*/request.json`、`terminal.json` | 每次物理尝试的原始请求与HTTP响应、状态、时间和usage |
| `finals/*.json` | 每条逻辑路径结束后立即落盘的最终结果；不等整块结束才保存 |
| `pipeline.jsonl`、`issues.jsonl` | 阶段推进、缺项、停止原因及异常调用栈 |
| `capacity_samples.jsonl`、`capacity_timeseries.json`、`progress.json` | 每秒追加落盘的容量样本、终结汇总和最新状态；包含许可、实际HTTP在途、排队、隔离剩余时间和批次节奏，不冒称服务端解码并发 |
| `paths/`、`db_traces/`、评分与成本文件 | 最终答案、数据库证据、逐题评分和全部尝试成本；未知值不补0 |

`send_started`表示客户端进入发送动作，不保证服务端接收；是否写完、是否收到HTTP响应另有字段。原始终结文件和账本不可覆盖。模型成本按物理request_id去重；数据库重放和控制成本单列。

`endpoint_recovery`事件记录端点减半/恢复；每次终结记录基础与实际响应超时。`case_error`、`scoring_error`与阶段问题记录包含任务身份和异常栈，方便随后排查。运行状态显示配置容量、实际容量和连续成功数。

## 入口

仅准备，不打开服务、不领取调用额度：

```powershell
python -m engine.cli prepare-pipeline CONFIG.json --output NEW_PREPARATION_DIRECTORY
```

`prepared_plan.json`明确标注 `admitted_for_execution=false`。它不是执行授权；新API的模型、容量、配置和源码须与新冻结/准入一致。

接入新API并完成一次执行准入后，后台启动一次：

```powershell
python -m engine.cli launch-pipeline CONFIG.json --logs NEW_LOG_DIRECTORY
```

该命令返回后子进程继续。Windows隐藏窗口，其他系统独立会话；无需定时唤醒聊天来发送下一批。配置、准入和私有key引用都来自本机文件；日志不包含密钥。

查看与停发：

```powershell
python -m engine.cli monitor RUN_DIRECTORY
python -m engine.cli drain RUN_DIRECTORY
```

当前新模型为`deepseek-v4.1-flash-1017-n72-75`，配置容量32，temperature 0.2、top_p 0.72、chat_template_kwargs为thinking=true与reasoning_effort=50；私有key从文件读取。已写入本机动态池和模型profile，未启动正式实验，新的正式模型/输入/资源与预算冻结仍需单独落实，不能拼接百灵结果。

矩阵入口：`python -m engine.matrix run PLAN_JSON RUN_DIR`。每个可运行格引用一份已封印的现有pipeline配置，复用同一引擎的预算、动态许可和落盘逻辑；矩阵层不另造HTTP客户端或重试器。`audit`只检查前置条件，不能当作冒烟通过；`watch`是只读Rich墙。

新DeepSeek支持`smoke_T1`：允许预先固定的小样本走与正式相同的数据库/反馈/评分代码，但不触发正式主表汇总。正式`formal_T1`仍强制2348全量。Direct+反馈是共享Direct路径的视图，不再次发模型。单元格缺适配/资源时写缺项后进入后续独立格；普通case异常写独立失败，未知计费状态、证据写入失败、身份错配仍保留硬停止。

远程任务墙通过独立`engine.mirror`发布只读快照，发布失败不控制模型收发。新端点32是容量上限，不等于持续32个解码任务；滚动补位，仅通信失败触发一次减半与响应超时翻倍，恢复期连续3次成功回到当前配置。

2026-10-28调研补修：中断任务保留为`incomplete`且不自动重发，后续独立任务可继续。它不是“已重建并补齐中断任务”；该任务仍需根据账本逐请求核对后，在新版本中恢复。普通块级停止保存失败后继续；人工DRAIN、预算耗尽、未终结计费请求、身份/持久化错误仍停止，并为后续任务保存`skipped.json`，不再静默消失。

旧retry中仅`recovery_cap/recovery_min_cap`两项已移除字段允许带警告迁移；其他未知字段明确报错，避免拼写错误静默改变实验策略。旧源码冻结仍保留，不允许把旧v7配置直接当新源码准入。等待容量期间每最多60秒追加状态；人工停发与容量超时分开记录。
